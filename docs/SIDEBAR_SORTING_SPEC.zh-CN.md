# 全侧栏独立排序功能规格 V2

更新：2026-09-30。性质：产品需求与后续实现规格，**不是已实现功能清单**。[English](SIDEBAR_SORTING_SPEC.en.md)

## 1. 本次扩展与截图证据

原方案只覆盖单个项目里的聊天。本次扩展为：**置顶、项目列表、最近、自定义分区、单个项目内聊天**，每个区域的三点菜单都能设置其直接列表的排序，并独立保存。

用户提供的截图能确认“项目”和“最近”的区域菜单已有“整理侧边栏”“聊天排序方式”等入口；没有展开排序子菜单，因此不能从截图判断其选项、保存范围或是否全局共享。“置顶”入口属于本次用户提出的需求，未在这两张截图中展开验证。公开文档仅描述通用界面，不上传含私人项目名称的截图。

实施前必须核实当前版本的每个原生入口实际控制什么范围。能复用且范围正确时，扩展原有入口；若原入口实际修改全局设置，应保留并标注全局含义，另提供明确的“本区域排序”。不得出现两个同名、不同作用范围的菜单。

## 2. 排序入口与作用对象

| 区域 | 三点菜单建议名称 | 排序对象 | 不能产生的副作用 |
| --- | --- | --- | --- |
| 置顶 | 置顶项排序方式 | 置顶区域直接显示的聊天、项目等条目 | 不置顶/取消置顶，不改变项目内部聊天顺序 |
| 项目 | 项目排序方式 | 项目文件夹本身 | 不把“项目排序”误当成各项目内聊天排序 |
| 最近 | 最近聊天排序方式 | 最近区域按原生规则应显示的聊天 | 不改变历史记录、归属、归档状态或其他区域的顺序 |
| 自定义分区 | 本分区排序方式 | 此分区直接包含的项目或聊天 | 不移动条目到别的分区，不改变子项目内聊天顺序 |
| 单个项目 | 聊天排序方式 | 当前项目内聊天 | 不影响别的项目及项目文件夹在侧栏的位置 |

所有入口统一提供“最近更新 / 创建日期 / 名称 / 手动”，非手动模式提供升序/降序，另提供“手动调整顺序…”和“恢复本区域默认排序”。创建日期等字段无法可靠取得时，选项禁用并说明原因；不提供会静默使用别的字段的伪选项。空区域也可保存偏好，第一条新内容按该偏好显示。

示例：项目列表按名称；项目 A 内聊天按创建日期；项目 B 内聊天按最近更新；置顶按手动；最近按最近更新。五种选择同时生效，互不覆盖。

## 3. 不同区域的排序语义

### 3.1 置顶

保持原生的置顶成员集合和显示层级。若原生在同一平面混排聊天和项目，排序也对这一个平面生效；若原生已有分组或固定块，则分别在可排序块内操作，不跨越固定边界。不得为了排序而重新分组。

项目条目用项目元数据，聊天条目用聊天元数据。置顶时间不等于创建时间；将来若新增“置顶时间”，必须单列。进入手动模式时快照当前有效顺序；新置顶条目追加末尾。取消置顶只移除成员，不删除聊天或项目；同一条目重新置顶时可恢复保留的历史位置，没有历史位置则追加末尾。

### 3.2 项目列表

按名称只比较项目名称，按创建日期只使用项目本身的可靠创建时间。不能用目录文件时间、最早聊天时间或首次被插件看见的时间冒充项目创建时间。

“最近更新”优先使用客户端明确提供且语义一致的项目活动时间；只有能得到完整、符合当前显示范围的聊天集合时，才能以其中最大的真实更新时间计算项目活动时间。不能用已加载一页的最大时间代表完整项目。两者均不可得时禁用该模式并解释，不能暗中切换到名称排序。

### 3.3 最近

保留原生筛选和成员规则：是否包含置顶聊天、是否隐藏项目内聊天、归档与来源过滤均由原生视图决定。排序只改变成员的显示顺序，不主动扩大集合或重复插入聊天。

原生“今天/昨天/更早”时间分组在最近更新模式下可保留，但分组日期必须与排序时间字段一致。创建日期模式如保留分组，必须按创建时间分组；名称或手动模式应在本区域切换为平面列表，避免日期桶破坏全局名称/手动顺序。无法安全切换分组的适配器应明确限制为“分组内排序”，不得声称全区域排序。

### 3.4 自定义分区与单个项目

自定义分区沿用置顶的直接成员/固定块规则，按稳定分区 ID 保存。分区改名或移动不丢失设置。条目移入分区后服从目标分区排序；该项目内部聊天偏好保持不变。

单个项目继续按稳定项目 ID 保存聊天偏好。项目是否置顶、归属哪个分区，不应改变该项目内部排序配置。云项目和远程项目要分别完成数据与菜单适配后才能列为支持。

## 4. 独立保存、继承与恢复

排序有两个维度：**容器内直接条目的顺序**与**子项目内聊天的顺序**。容器设置不向子项目级联，也不修改客户端全局默认。

生效规则：当前范围有显式覆盖时使用该覆盖；没有覆盖时保留客户端在该范围原有的默认行为，包括原生优先级、手动顺序和固定边界。原生聊天全局默认变化只影响本来继承它、且无覆盖的聊天视图；项目列表、置顶和自定义分区是否继承全局值必须以原生契约为准，不自行推断。

“恢复本区域默认排序”只清除当前范围的覆盖，恢复对应原生行为；不重置其他范围，不移动/删除内容，不清空账号配置。不提供容易误触的隐式全局重置。

拟议的 V2 配置结构（尚未迁移现有运行时）：

```json
{
  "schemaVersion": 2,
  "scope": {
    "accountId": "account-id",
    "surface": "codex",
    "viewScopeId": "stable-view-id",
    "kind": "project-chats",
    "id": "stable-project-id",
    "source": "local",
    "hostId": "stable-host-id"
  },
  "sort": {
    "mode": "name",
    "direction": "asc",
    "manualIds": [],
    "locale": "zh-CN"
  },
  "revision": 1
}
```

`kind` 为 `pinned-items`、`project-list`、`recent-chats`、`section-items` 或 `project-chats`。内置区域用固定 ID，自定义分区和项目用原生稳定 ID，禁止名称/显示位置作主键。跨主机混合区域按其稳定视图范围保存；手动列表中的实体标识由来源、主机、类型、原生 ID 共同组成，避免不同来源的同 ID 条目串用。不要把当前窗口焦点所在主机误当成混合区域的归属。

沿用宿主偏好服务；无同步能力时明确标注仅本机。写入失败回退视图并显示错误；损坏配置保留以供恢复，不自动覆盖。多窗口通过版本号/宿主冲突机制检查并发写入，不能让旧的手动编辑窗口静默覆盖新设置。未实现同步时不得宣传已支持。

V1 项目聊天配置应一对一迁移到 V2 的 `project-chats`，保留原排序和手动 ID；其他新范围初始无覆盖。迁移前保留旧配置，校验成功后一次性提交；失败沿用旧版本。重复迁移不得再改顺序。此流程是后续要求，本次不执行迁移。

## 5. 共同行为与边界

| 情况 | 规定行为 |
| --- | --- |
| 日期与方向 | 最近更新/创建日期默认降序，名称默认升序；字段单位统一为 Unix 毫秒 |
| 缺失日期 | 部分条目缺失时始终置后；全部不可用时禁用该模式；明确提示元数据不完整 |
| 名称 | 按保存的排序语言进行自然排序，数字 2 在 10 前；同名以复合稳定 ID 打破平局 |
| 手动模式 | 进入时快照实际显示顺序；更新和重命名不重排；新条目追加；支持拖动和键盘上移/下移 |
| 编辑中成员变化 | 保存前验证范围、成员集合和配置版本；变化时提示刷新，不静默丢弃新条目 |
| 归档/恢复 | 原生规则决定可见性；可保留手动位置以支持恢复，永久删除后清理失效引用 |
| 暂时筛选 | 不用筛选后的子集覆盖完整手动顺序；受限适配器在筛选状态禁用手动保存 |
| 懒加载/分页 | 完整排序需服务端有序分页或完整元数据；只处理当前页面时必须标注“仅已加载条目” |
| 刷新与重启 | 偏好保存成功与界面补丁重载分别验证，不能混为一谈 |
| 状态更新 | 新消息只改变依赖更新时间的范围；不修改手动/名称/创建日期范围 |
| 可访问性 | 单选状态、作用范围说明、键盘方向键/Enter/Esc、关闭后焦点返回；中文英文语义一致 |
| 不支持的版本 | 保持原始菜单与顺序，并提示范围不受支持；不得绕过指纹校验 |

## 6. 当前实现与后续任务

| 能力 | 本次文档更新时的状态 |
| --- | --- |
| 单个未置顶本地/远程项目的已加载聊天排序 | 现有实验适配器已有；实机验证边界见验证记录 |
| 置顶区域三点菜单和置顶项排序 | 新增需求，未接入 |
| 项目区域三点菜单和项目文件夹排序 | 新增需求，未接入 |
| 最近区域独立排序和时间分组切换 | 新增需求，未接入 |
| 自定义分区独立排序 | 新增需求，未接入 |
| 置顶项目的内部聊天菜单、云项目菜单 | 后续适配范围，现有适配器不支持 |
| V2 配置迁移、完整分页排序、多窗口冲突处理 | 后续设计要求，未实现 |
| Mac 原生菜单 | 仅启动器预览，无已验证的 Mac 渲染器适配 |

建议实现顺序：核实当前版本原生菜单与数据契约 → 实现 V2 范围键及无损迁移 → 项目列表和最近范围 → 置顶与自定义分区 → 分页/分组/多窗口 → Windows 实机逐范围验收 → 单独完成 Mac 适配。每一步必须按范围维护支持状态，不能用一个成功菜单代表全部侧栏。

## 7. 验收清单

以下均为后续验收目标，尚不是通过记录。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| S01 | 五类三点菜单 | 入口作用范围明确、不重复、不误改全局 |
| S02 | 项目名称排序 + 项目 A 创建日期 + 项目 B 手动 | 三种顺序同时保留，互不覆盖 |
| S03 | 置顶混合项目/聊天 | 只重排允许的直接成员，不改变成员与层级 |
| S04 | 项目创建/活动时间不可得 | 对应选项禁用，不伪造日期或默默改用其他字段 |
| S05 | 最近按名称/手动 | 日期桶不破坏排序，原生筛选与成员集合保留 |
| S06 | 自定义分区改名、移动、条目迁入 | 范围配置保留，子项目内部配置不变 |
| S07 | 全局默认变化、当前范围恢复默认 | 有覆盖的范围不受影响；恢复仅清除当前覆盖 |
| S08 | 同名项目、跨账号/来源/主机同 ID | 设置和手动位置不串用 |
| S09 | 未加载历史、多页、临时筛选 | 不把局部排序宣称为完整排序，不丢失未显示的手动 ID |
| S10 | 新增、重命名、更新、置顶/取消、归档/恢复 | 各模式按规定稳定更新，无删除或重复 |
| S11 | 配置写失败、损坏、并发编辑 | 报错并保留可恢复状态，不显示虚假保存成功 |
| S12 | V1 迁移、重复迁移、迁移失败 | 原项目配置不变，失败可回退，新范围保留原生默认 |
| S13 | 退出/重开及多窗口 | 分别核验偏好恢复、插件加载和窗口同步，不互相替代证据 |
| S14 | 中英文、键盘、空范围 | 标签和作用对象一致，可访问操作完整 |
| S15 | 不兼容版本或尚不支持的平台 | 原菜单可用，明确拒绝未验证的注入 |

当前运行时证据见 [验证记录](VALIDATION.md)；对开发者的说明见 [Developer brief](FOR_CODEX_DEVELOPERS.md)。本次仅更新文档，不改变用户现有侧栏顺序、偏好、启动器或安装包。
